# Token Town — approved product rules

## 定位

5–10 分钟的本地城镇经营游戏。同步 AI token → 金币 → 买入并布置建筑 → 通过道路改善服务 → 完成委托 → 土地、建筑和装饰解锁。主屏始终是 3D 河谷小镇，现代 DOM 字体与安静 HUD。

入口取建筑朝向前方中间的格子。道路通过镇公所入口 BFS 求连通；服务沿连通道路最短路径传播。候选服务按距离、店铺稳定 ID、住宅稳定 ID 排序，容量用完后停止；同距结果不会随机变化。居民和动画完全不参与规则计算。视觉居民按实际位移迈步、摆臂，沿道路边界内缩形成的圆角闭环巡游，保持前后间距；固定车道不反复改向。夜晚逐户开门进入住宅睡觉，清晨预约路面空位再出来。纯装饰不会替代食物、休闲或绿地服务。

## 经济

每 10,000 新 token 铸 1 金币，零头累积。首次同步允许兑换历史；每个项目保存只增不减的兑换高水位，重复同步、历史删减 / 恢复都不会重领。没有项目等级倍率。

六章首次基础目标解锁经营补贴权益 5 / 10 / 15 / 20 / 25 / 30。已付累计补贴 ≤ floor(累计 token 金币 / 5)。未付款权益保留，下一次 token 同步结算。提高星级不再增加补贴。

## 六章与永久星级

基础目标全部满足后获得一星并开放下一章。两个额外目标各加一星，最高三颗；已记录星级永久保留，额外星级解锁对应建筑纪念配色。镇公所庭院原生 3D 纪念星同步展示成果。

|---|---|---|
| 1 在这里落脚 | 4 户连路且有食物 | 2 户绿地；道路 ≤16 |
| 2 绿荫街坊 | 6 户食物；4 户绿地 | 6 户绿地；道路 ≤24 |
| 3 热闹市集 | 8 户食物；6 户休闲 | 8 户休闲；6 户全部需求 |
| 4 河的另一边 | 桥连接，北岸 2 户食物，南岸 4 户食物 | 北岸 4 户食物；两岸各有全部需求住宅 |
| 5 紧凑而舒适 | 12 户全部需求；道路 ≤40 | 道路 ≤36；14 户全部需求 |
| 6 我们的河谷 | 16 户全部需求，两岸各至少 4 户，连路钟楼 | 20 户全部需求；道路 ≤64 |

第一章介绍连路和食物，第二章引入绿地，第三章引入休闲。需要查看入口和服务覆盖时，选择建筑即可显示；服务商店显示自身已服务住宅和仍缺服务住宅。

委托进度统计获得服务的**住宅**，同一需求每栋只计一次；重复覆盖不会叠加。目标卡提示住宅不足或缺少的服务。委托面板区分已摆住宅、连路住宅、食物和绿地满足数，支持逐栋查看缺少服务的具体原因并定位建筑。商店详情区分范围内住宅与实际分配的服务容量；公园显示三格范围及真正满足绿地的住宅，入口未连路时不会显示有效绿地覆盖。范围可视化和反馈使用与规则一致的入口、距离和服务分配结果，不改变存档或奖励。

## 控制与存档

选择建筑即显示跟随鼠标的半透明模型，目录收起；可直接从目录拖出。落地通过规则校验后才扣费，无效位置标红。R 旋转，右键 / Esc 取消，中键拖动浏览；正常浏览时按下拖动平移。触控板模式默认两指上下滑控制俯仰、左右滑控制旋转，捏合（Ctrl-wheel）缩放，Shift + 两指滑动平移；鼠标模式保留滚轮缩放。俯仰限制在 26°–72°，世界保持水平；手势按时间平滑收敛，不持续自行旋转，减少动态效果时即时响应。聚焦、俯瞰及缩放按钮同样平滑过渡，回到小镇恢复 40° 俯仰。镜头变化时待放建筑重新投射到鼠标下方。Q / E 或旋转按钮按住持续旋转，松开停止。

真实与演示存档独立；每个模式保存金币账本、项目高水位、建筑库存 / 布局、章节 / 关卡星级、配色、关卡进度和设置。原街机存档不迁入。没有本地历史时，不自动制造真实 token；明确提供演示入口。

触控板映射参考 [Blender 精确触控板导航](https://developer.blender.org/docs/release_notes/3.3/user_interface/) 与 [SketchUp Trackpad Controls](https://help.sketchup.com/en/trackpad-controls)：采用保持水平的转台旋转、修饰键切换平移 / 缩放，以及独立输入模式。浏览器无法可靠区分精确鼠标与触控板，所以不根据滚动数值自动猜设备。

暂不加入战斗、多人、随机抽取、复杂生产链、室内装修或第二货币。
