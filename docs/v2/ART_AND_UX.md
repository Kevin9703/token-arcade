# 美术、UI 与交互规范

版本：0.1 / 提案。本文从游戏玩法推导美术与 UI，不能把概念图或技术容易实现的样式当作最终设计。

## 1. 最重要的视觉要求

**第一眼看见的是一间精致像素游戏里的街机小屋。**

主画面的价值在房间、机台、角色和生活细节。去掉所有文字后仍应是一幅可信的可玩场景；加回文字后，文字坐在门牌、机台铭牌、计数器和游戏对话框里。

用户已经明确否决本轮“网页式首页”：平面深色标题栏、底部大卡片、网页按钮、纸色 DOM 手册、简陋方块伙伴。该方向不能作为继续润色的基础。

### 艺术方向（提案）

雨夜里的私人街机小屋。深木与暗紫墙面，暖灯落在地板上，窗外是安静的蓝色城市；机台的少量青绿、莓红和金色灯光形成焦点。温暖、有收藏感，但保留街机的机械乐趣。

不是写实 3D、不是 glossy 图标合集、不是将图片贴到 CSS 卡片上。大背景与小物件必须遵守同一视角、阴影方向和像素密度。

## 2. 世界、像素与字体规范

| 项目 | v0.1 制作规范 |
| --- | --- |
| 场景逻辑尺寸 | 保留 1600×1000 交互坐标；美术以 400×250 像素母版的密度为目标，优先 4×整数映射 |
| 相机 | 轻俯视、正面 RPG 房间；明确顶面与落地基线，不混用等距菱形视角 |
| 像素密度 | 主体同屏每个美术像素约 4 个逻辑像素；特效可用 2 或 4 的整数网格；不把高分辨率笔触当像素细节 |
| 描边 | 深紫或深木色分层轮廓；同类对象同描边厚度；避免所有元素用白线围住 |
| 调色板 | 暗影 #171322、木影 #3B2335、木色 #8B503C、暖光 #F3C47D、电力 #70C9BD、霓虹 #CE739C；生产时抽样统一，不用代码任意染原图 |
| 光线 | 以固定顶灯为主，机台屏幕与按钮局部发光；不用大面积 CSS/Canvas 高斯光污染场景 |
| 中英字体 | 游戏像素字体，中文完整字形优先。由已获许可、覆盖所有必需字符的本地字体完成正式排版，禁止上线依赖远程字体请求 |
| 文本密度 | 首页同时突出的动态文本不超过：金币、一个对象提示、一个当前目标、必要模式标识；其余信息走近再看 |

400×250 是密度目标，不是把现有高分辨率图缩小后最近邻放大就算美术完成。需要像素簇清理、轮廓修正和关键物件重绘，确保机器能读、角色有表情、中文不糊。

1600×1000 坐标暂保留以降低程序风险，不等于所有 UI 都在整幅画布上任意摆。游戏 UI 单独使用稳定布局锚点。

## 3. 房间构图

```text
┌─ 肖像/简短身份 ─── 房间实体招牌 ─── 金币计数器/菜单 ─┐
│          墙面细节、雨夜窗、吊灯、少量展示物           │
│  项目展台（4机位）     储蓄罐      扭蛋角     展示架    │
│                                                        │
│     摆设角落           店长 + 小光                      │
│                  可走动的地板和地毯                    │
│  手册物件/下一步提示                    小型工具挂架    │
└────────────────────────────────────────────────────────┘
```

构图要求：

- 房间占画面主体，UI 不另造网站页头与页脚。
- 机台直接摆在房间地台上；名称短牌跟随机台，不构成横向统计卡片。
- 储蓄罐是首次主动作焦点；旁边留出收获演出空间。
- 角色尺寸约为机台高度的 45%–60%，伙伴约为角色高度的 35%–55%；最终用同屏样板核对。
- 正常状态只突出一个交互对象。悬停以地面小标记、轮廓高亮或图形提示表示，不给整个对象包网页边框。
- 空展示架要美观，不用几十个灰锁提醒用户“什么都没有”。奖品目录才显示完整缺失项。
- 高亮层、碰撞层、装饰层明确分开。不能把图片里看似空的地方随意当人物可走区域。

## 4. 信息架构：从物件进入，而非从导航栏切换

| 场景物件 | 主动作 | 打开的体验 |
| --- | --- | --- |
| 储蓄罐 | 同步 / 收获 | 留在房间，通电和金币演出 |
| 项目机台 | 走近看看 | 单机近景、进化目标、心爱标记 |
| 小光 | 打招呼 | 短回应；再次打开伙伴进化册 |
| 成长手册 | 看下一份礼物 | 游戏内翻页手册，一页突出一章 |
| 扭蛋机 | 投币 | 对机器的近景操作和出球揭晓 |
| 展示架 | 看我的宝物 | 收藏册、用途、放置/装备 |
| 布置工具 | 整理房间 | 布置模式、库存物件托盘 |
| 门口菜单挂架 | 设置 | 音量、语言、来源、存档等基础选项 |

键盘/无障碍导航仍需覆盖同样动作，但默认不把它排成一个占据画面的 SaaS 导航条。

## 5. 四个关键界面

### A. 主房间

休息态先让玩家看见房间。金币、模式标识保持可读；不在每台机台旁常驻 token 总量、来源、基础币、倍率四行字段。

未开始：储蓄罐短提示。可领奖励：手册上一个柔和书签标记。没有新 token：平静回执，可继续布置。升级发生：机台局部电力传递，不整个页面闪烁。

### B. 机台近景

大机台是主角，占主要画面。项目名在招牌；等级在机器铭牌；屏幕承担“当前电力”和下一级反馈。旁边最多一个小维护窗口，显示下次进化的剪影与解锁门槛。

按“进化图鉴”才展开五阶段横向卷轴。不能默认把机台、大统计板、五个数字卡片、奖励历史同时摆满。

### C. 成长 / 伙伴手册

采用游戏内像素书册或票册美术。每页一件大礼物、一句话、一个门槛、一个明确动作。章节目录为书页标签，可翻页；已领取页留下贴纸/印章。伙伴页展示当前形态与下一形态，使用实际角色资产。

禁止采用普通网页白底列表、纵向一排同样的进度条和绿色按钮。复杂文字可以由 DOM 实现可访问层，但可见外观、像素边框、字体、动效必须遵守游戏 UI 规范。

### D. 扭蛋与收藏

先看机器，手柄可操作。扭蛋结果卡是从机器出来的一张小奖券或打开的胶囊，不是页面弹出的通用 modal。

新物件放大展示 → “摆进小屋 / 收好”。收藏目录按主题/用途浏览，不默认按稀有度组成数据表。兑换价格、概率说明和重复处理能查到，但不抢夺主景。

## 6. 动作、反馈与声音

以下时长为初始制作目标，须试玩调整；“减少动态效果”可压缩/替代，交易结果不依赖时长。

| 时刻 | 视觉与声音 | 建议时长 |
| --- | --- | --- |
| 对象悬停/聚焦 | 地面标记、局部亮边，不缩放全场景 | 即时 |
| 同步请求中 | 罐内小电流循环，按钮防连发 | 跟随真实请求 |
| 收获 | 受影响机台→储蓄罐电力，金币跳出并收进计数器 | 0.9–1.5 秒 |
| 数字升级 | 屏幕亮一下，小铭牌翻到新等级 | 0.4–0.7 秒 |
| 阶段进化 | 停一拍、轮廓亮起、切换整机、小范围碎光 | 1.2–1.8 秒，可跳过 |
| 拉扭蛋 | 手柄压下→胶囊滚动→掉出→打开 | 1.8–2.5 秒，可加速 |
| 新奖品 | 物件与用途、短音色、摆放提示 | 玩家确认结束 |
| 重复 | 小星尘吸收，不占完整新物品演出 | 0.4–0.6 秒 |
| 放置 | 落地轻弹、接触阴影、小敲击音 | 0.15–0.25 秒 |
| 伙伴 | 呼吸、转头、跟随、被点时短回应 | 小幅、间歇 |

不做招牌随机高频闪烁；不以屏幕抖动营造所有稀有度。一次跨多级演出只取最高变化，剩余写真实收获摘要。

## 7. 美术资源生产约定

### 先做同屏样板，后做资源全集

第一张样板必须同时包含：房间、普通与进化机台、店长、小光、储蓄罐/扭蛋机、一个 UI 对话框、一件摆放物。用 100% 和实际游戏缩放检查，而不是分别觉得每张图都漂亮。

每个资产交付：源文件、处理后 PNG/WebP、透明边界、像素密度、脚底 pivot、逻辑大小、碰撞框、挂点、帧率/帧表、颜色状态、许可/来源说明。精灵图集不能靠每次运行扫描边缘猜裁剪。

字符、项目名、货币、等级不烘焙进图。背景的空招牌和陈列架是挂点，不可用烘焙假奖励代替真实库存。

这些由内置 imagegen 生成，是**未验收的概念候选**。存在必须检查的问题：细节密度可能过高；角色四步动画可能没有真正的左右脚差异；伙伴与人类分格高度可能不一致；图集透明边缘可能有杂色；机台与房间像素密度未统一。不能直接宣布为精灵成品。

本轮不再继续生成更多物件，先由总策划和同屏样板决定是否采用。提示词与生成方式在 [决策记录](DECISIONS.md) 留档。

## 8. 输入、尺寸与可访问性

桌面优先，但不能把 1600×1000 整幅缩到手机就声称已适配。

- 鼠标：点击对象；点击地面移动；悬停提示不提供独占信息。
- 键盘：方向键/WASD 移动；Tab 或对象循环切换可交互目标；Enter/E 操作；Esc 返回。弹窗打开暂停世界输入。
- 触屏：点对象直接操作；点地面走动；放置用选中→点位置，不依赖拖拽/悬停。
- 小屏：优先使用靠近的房间视窗、对象焦点切换与独立缩放的游戏 UI；不照搬桌面四机位一屏。360×800 需可完成整个核心流程；若首版尚不达标，明确标记桌面优先，不以六个网页按钮作最终移动 UI。
- 色彩：等级不仅靠颜色，还靠灯数、轮廓、等级数字；稀有度有名称。
- 文字：中文不缺字；文本溢出有可展开完整名称；主按钮触摸区域不小于 44 CSS px。
- 动态：尊重减少动态效果；同步结果和领取不靠特效独占传达。
- 音频：可静音；用户首次交互前不自动播音。
- 可访问层：对象名称、当前状态、可执行命令对键盘/读屏暴露；和 Canvas 命令使用同一来源，不另写第二套交易逻辑。

## 9. 美术与交互验收门槛

1. 用户认可同屏样板具备精致像素游戏感，再进入同类资源扩展。设计师自认“比之前好”不是标准。
2. 原尺寸、1440×900、1280×800 截图：无拉伸、黑底假透明、浮空、错落地面、重复页面框。
3. 灰度看主画面：仍能分辨角色、可交互物和背景；局部光不吞轮廓。
4. 1/4/20 个项目、0/1/50 个收藏、长中英文名均有可用布局。
5. 收获、进化、抽奖、摆放各录一次短流程；核对音画和最终状态。
6. 主画面若仍首先被看成网页布局，返工构图和 UI 语言，不加更多边框、阴影或素材来掩盖。
