## 先读这一页

**做一款精致的像素养成游戏：把日常 AI 编程留下的 token，变成一间有项目记忆、有伙伴、有收藏、能按自己喜好布置的街机小屋。**

玩家回来，是想看看自己的机台和伙伴长成什么样，拆开一份期待的礼物，再把小屋改得更喜欢一点。金币和数字只负责支撑这件事。

当前工作的顺序调整为：**游戏策划 → 完整闭环和数值验证 → 美术与交互样板 → 程序落地 → 试玩修订**。不再用先画页面、再补玩法的方式推进。

## 提案中的核心取舍

- 以**个人养成、收藏和空间表达**为主，不加入营业收入、顾客满意度、打工任务或战斗。
- token 是唯一外部成长输入；金币由它产生。走路、抚摸、布置只提供互动和表达，不刷资源。
- 一台机台属于一个真实项目；保留 50 级、5 阶段的成长身份。
- 一位固定伙伴“小光”（暂定名）随累计 token 进化。收藏伙伴是可摆放来客，避免开局管理一群宠物。
- 确定的章节礼物负责“我知道下一步会得到什么”；扭蛋负责惊喜；布置负责“奖励真的改变我的小屋”。
- 不做签到、体力、离线收益、缺席惩罚。已有进度永久保留。
- 首个制作切片是**一间房间的一次完整成长体验**，不是五个独立页面一起换皮。

## 文档优先级

用户最新明确指示 > 本目录中之后被确认的决策 > 本目录 v0.1 提案（本轮工作的设计依据） > 历史 PM/美术文档 > 旧实现习惯。

v0.1 的数值以当前代码为保守基线，并不代表用户已经认可所有新增设计。旧 `docs/GAME_ECONOMY.md` 的 1,000 token/币、10/90 抽奖价格已过时；当前实现为 10,000 token/币、25/225。遇到冲突先更新这里的决策记录，再改系统，不能默默在不同页面使用不同规则。
